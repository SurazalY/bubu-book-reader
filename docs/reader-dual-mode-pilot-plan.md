# 原版 PDF / OCR 文字双模式三书试点实施计划

> 状态：v0.1 决策冻结稿  
> 日期：2026-08-15  
> 适用分支：`codex/reader-ocr-checkpoint-20260815`  
> 本文件只冻结三书试点的业务、数据和验收边界，不代表已经开始修改产品代码。

## 1. 目标与范围

本轮只完成三本书的可验证试点，不直接扩到 49 本：

1. 同一本书提供“原版 PDF”和“OCR 文字”两种阅读模式。
2. 两种模式使用同一 `bookVersionId + physicalPageNo`，共享页码、上次位置、阅读进度、整页书签和课堂同步页。
3. 原版模式优先保留原书排版；文字模式优先保证可读性、可选文、摘录、批注和 AI 交互。
4. AI 只使用当前页以及学生产生过有效阅读事实的页面，不以“最高读到页”推断中间页面已经读过。
5. 先用三本差异明显的书验证内容链、阅读器、AI 和真机体验，再决定是否批量导入其余 46 本。

本轮不做：49 本全量导入、逐字几何校准、原版 PDF 上的 OCR 透明选区层、OCR 自动语义改写、主动阅读干预策略、家长端或电子书包新功能。

## 2. 依据与权威顺序

遇到冲突时按以下顺序执行：

1. 本轮用户确认：三书试点；按 PDF 物理页分页；两模式共享页码与进度；文字模式负责选文和 AI。
2. 当前仓库的冻结阅读监测契约与领域/API 契约。
3. 2026-08-15 设备迁移说明与 OCR 验证证据。
4. 2026-08-07 正式 v3 交接及补充材料中的产品、学生端和 AI 契约。
5. 更早的 Plan、讨论记录和旧源码只用于追溯，不覆盖以上冻结项。

关键历史业务结论已经确认：

- “读伴”首先服务沉浸阅读，不把学生端做成测评、排名、贴标签工具；不轻易打断、不剧透。
- AI 只存在于整书阅读器，默认由学生点击入口、选文或主动输入触发。
- AI 知道当前书、当前物理页、选文、最近对话和有效已读范围；书内事实必须引用真实原文并映射真实页码。
- 前端不得提交任意字符串充当可信书内原文；服务端根据稳定块 ID 和字符范围从书库重建、校验证据。
- 多段跨页选文、摘录、批注和问竹娃已经属于既有产品方向。

## 3. 已确认的现状

### 3.1 OCR 内容

- 49 个 OCR job 均有报告；合计 8,602 个物理页 JSON，报告中的终态页均为 `ok`，没有 OCR job 失败页。
- OCR 页面以顺序文字块保存，文本识别结果已足够进入“校验和整理”阶段，不需要重新跑一轮全量 OCR。
- 这些结果仍是 `work/text-ocr-v1/jobs/...` 下的原始账本，不是应用可直接发布的书籍包：当前归档中没有 `book-parser/releases/` 成品。
- 现有原始块使用 `lineBBox`，且全部标记为估算坐标；抽查中约 26.5% 的块只有整页框。
- 扩大几何验证只有 561/2,556 块成功，成功率 21.95%，并发现拼音带错配、跨行漂移和漏行。它不能用于原版页上的可选 OCR 覆盖层。
- 现有 `book-package/v1` 构建器期待 `bbox` 和合并响应，且仍有样书标题硬编码，不能直接消费当前逐页 `lineBBox` 账本。
- OCR 报告验证的是文件齐全、JSON、页数、尺寸和框范围，不等于逐字准确率。抽样文本已能看到疑似错字或漏字，因此发布前必须有人审抽样和可追溯修订。

结论：OCR “识别作业”已完成；“校验、规范化、打成应用发布包并导入”尚未完成。

### 3.2 当前应用

已经具备：

- `books / book_versions / book_pages / book_blocks / book_assets` 书籍领域模型。
- PDF、封面、页图资产登记和页/块导入能力。
- 固定页码 Reader、单双页、翻页、目录、上次位置、阅读事件、书签、摘录、批注、多段选文托盘和 AI 面板。
- AI 证据块、引用校验、防剧透框架和服务端证据读取。

尚有明确差距：

- 当前 Reader 把页图和透明 OCR DOM 叠在一起，尚未拆成真正的“原版 PDF / 文字”双引擎。
- 当前原书资产没有通过学生端 DTO 暴露给 Reader，也没有 PDF.js 阅读视图。
- 当前页面图片叠字依赖坐标，而现有 49 本坐标质量不满足使用条件。
- 当前 AI `readScopeProvider` 只接受当前页，未实现既定的“有效已读页面集合 + 当前页”。
- 当前跨页多段选择会汇总块 ID，但单一 `selectionRange` 无法表达多个页内字符范围，需要冻结数组契约。
- 新版阅读监测明确禁止用 `last_page_no` 推导已读页集合；现有摘要只保存最后位置和累计时长，没有逐页有效覆盖事实。
- 领域层有书籍导入能力，但没有面向这批真实 OCR 包的确定性导入命令、发布门禁和完整 HTTP/管理流程。

## 5. 冻结的产品与数据契约

### 5.1 页码

- `physicalPageNo` 是从 1 开始的 PDF 页索引，也是路由、进度、书签、课堂同步、AI 引用和两模式切换的唯一主页码。
- 印刷页码只作为可选 `printedPageLabel` 展示，不参与定位，不覆盖 PDF 封面、版权页等前置页。
- 文字模式不得把相邻 PDF 页内容合并，也不得因字号变化重新产生新的“逻辑页码”。允许在一个物理页内部流式排版和纵向滚动。
- 双页视图的主位置继续采用可见页中最小物理页码；最后停留页只代表位置，不代表完成度。

### 5.2 模式切换与共享状态

- Reader 只有一个权威位置状态：`bookVersionId + physicalPageNo`；模式是附加状态 `readerMode = original | text`。
- 切换模式后留在同一物理页，不另写一份进度。
- 上次位置、有效阅读、整页书签和课堂同步页共享。
- 摘录、批注、选文高亮以文字块和字符范围为锚，只在文字模式创建和编辑；原版模式可通过目录/列表跳回对应物理页查看这些成果。
- 阅读事件和逐页覆盖事实记录 `readerMode`，用于质量分析，但模式不得改变“是否读过该物理页”的业务含义。

### 5.3 原版 PDF 模式

- 使用原始 PDF 资产和 PDF.js 渲染，不把 200 DPI 重渲染 PNG 当作原版主数据。
- 保留原排版、插图和物理页；平板以单页优先，空间足够时可双页。
- 三书试点不在 PDF 上叠加 OCR 可选层，不提供原版页内划词；避免用低质量估算坐标制造错选和错引。
- PDF 加载、权限或完整性失败时显示明确错误状态，不伪造成功、不自动切换到另一模式。

### 5.4 OCR 文字模式

- 每个物理页生成有序 DOM 文本块；正文可调字号、行距和纸张色，但不能跨物理页重排。
- 每个块使用确定性 `blockKey`，建议为 `p{pageNo}-b{order}`；数据库 ID 可另外生成。
- 原始 OCR 保存为不可变 `rawText`；展示和 AI 使用经审核的 `normalizedText`。二者不得互相覆盖。
- 每条修订记录至少包含原文 hash、修订后文本、页、块、修订原因、修订人/工具、时间和规范化版本。
- 字符范围全部基于 `normalizedText`；书籍发布后，同一版本不得原地改变块文本和字符偏移，修订应产生新书籍版本。
- `lineBBox` 可保留作审计元数据，但三书试点的文字阅读、选择和 AI 不依赖它。

### 5.5 AI 可读范围与可信证据

- 可检索页面集合严格为：服务端已接受的有效逐页阅读覆盖集合，与请求时的当前物理页做并集。
- 不允许把 `1...last_page_no` 当作已读集合；跳到后页不会解锁中间内容。
- 当前页即使尚未达到有效阅读时长，也允许用于当前问题；离开后是否进入历史可读集合由有效逐页覆盖事实决定。
- AI 请求提交书籍版本、当前物理页、问题、`readRangeVersion` 和结构化选区，不提交任意原文作为可信证据。
- 多段选文冻结为：

```json
{
  "selections": [
    {
      "pageNo": 12,
      "blockId": "stable-block-id",
      "startOffset": 3,
      "endOffset": 18
    }
  ]
}
```

- 服务端校验每个页、块、偏移、书籍版本和已读范围，再从 `normalizedText` 重建选文；客户端 quote 只用于即时显示。
- 书内事实回答必须引用真实证据 ID；引用落到真实物理页、块和字符范围。证据校验失败时返回明确失败状态，不显示未经校验的答案。
- 三书试点保留既有“学生主动触发 AI”方式；基于停留、跳读或回读的主动干预属于后续独立项目。

### 5.6 逐页有效阅读事实

现有阅读摘要必须扩展一份逐页事实，不能从最后位置反推：

- 客户端沿用已冻结的稳定视图、可见性、租约和有效停留判定，累计每个物理页的有效毫秒数及已确认交互。
- 摘要 revision 携带按页累计值或确定性增量；服务端在与会话摘要同一事务中幂等写入 `reading_page_coverage`。
- 建议唯一键：`organization + actor + workspace + bookVersion + physicalPageNo`。
- 页面进入 AI 历史可读集合的条件是：至少有一段被服务端接受的正有效时长，或有一次被服务端接受的选文、摘录、批注、书签或 AI 提交交互。
- `readRangeVersion` 由服务端按有序页面集合及数据版本生成并返回；AI 请求携带该版本，服务端发现过期则显式拒绝并要求刷新。

## 6. OCR 发布包与质量门禁

### 6.1 新包格式

建立 `book-package/v2`，至少包含：

- 书籍元数据、版本、内容来源、使用/授权说明。
- 原 PDF 的相对存储键、SHA256、大小和页数。
- 每个物理页的宽高、`rawText`、`normalizedText`、有序块和稳定块键。
- 原始 OCR job、模型、提示词/解析版本和 source PDF hash。
- 规范化修订账本和质量报告。
- 不把本机绝对路径写入应用发布包。

### 6.2 三书验收门禁

1. 自动校验覆盖 614/614 页：页号连续唯一、源 PDF 页数一致、JSON 可解析、块顺序稳定、字符范围连续、所有 hash 匹配。
2. 每书人工分层抽样不少于 30 页，覆盖封面/目录、前中后段、纯文字、插图、多栏、低置信度和空页；book-001 额外覆盖拼音页。
3. 所有空 OCR 页与低置信度页必须逐页核对，不能把“有图无正文”和“漏识别正文”混为一类。
4. 抽样要求正文不漏段、不串页；影响语义、人名、数字、标题、标点成句的错误必须修订并留痕。
5. 任一本未通过时只修该书并重新抽样，不把未验收内容发布为 `published`。

首轮人工抽查的目的不是声称全书逐字零错误，而是建立可量化错误率和错误类型；三书试点结束后再根据实测决定 46 本的抽样比例与是否需要专项校对。

## 7. 实施工作包

### WP0：冻结契约与基线（1 人日）

- 将本计划的页码、模式、AI、逐页覆盖和 `book-package/v2` 结构拆成可执行接口/schema。
- 为现有数据库、前后端、OCR 归档和三书源 PDF 建基线 hash 与测试清单。
- 不修改既有阅读监测真值和护眼边界；新增字段不做旧 DTO 补零或双写兜底。

### WP1：三书发布包与 OCR 质检（3—5 人日）

- 编写确定性转换器，消费逐页 OCR job，而不是旧的合并响应格式。
- 生成 `rawText / normalizedText`、稳定块键、修订账本和质量报告。
- 完成三书自动校验、人工抽样、问题修订、复验并生成不可变 release。
- 提取并登记三本源 PDF、封面及版权/校方审查元数据；未完成外部使用授权时只允许内部试点标识。

### WP2：目录、导入与资产接口（3—4 人日）

- 增加必要数据库迁移：原始/规范化文字、规范化版本、印刷页标签、逐页覆盖事实。
- 实现可重复执行且 hash 校验严格的三书导入命令；重复导入不得重复写书、块、资产或发布状态。
- 导入先进入 draft，通过质量门禁后显式 publish。
- 学生端书籍 DTO 返回可授权访问的 `source_pdf` 资产和可用阅读模式；静态/对象存储路径只使用相对键。
- 补齐原 PDF 的范围请求、MIME、缓存和访问权限验证。

### WP3：双模式 Reader（4—6 人日）

- 把当前 Reader 的权威页码、顶部/底部控件、目录、书签、课堂状态和 AI 面板抽成模式共享壳。
- 接入 PDF.js 原版模式；接入按物理页分组的 DOM 文字模式。
- 增加明确的“原版 / 文字”切换，切换不换页、不重复进度、不丢课堂同步状态。
- 文字模式接现有选择、摘录、批注和多段托盘；原版模式不挂 OCR 透明层。
- 验证单双页、字号、页内滚动、跳页、返回恢复和 Android 横屏触摸。

### WP4：AI 范围与多选区证据（3—5 人日）

- 新增逐页有效覆盖的客户端累计、摘要字段、服务端事务和查询。
- 将 `readScopeProvider` 从“当前页单页”升级为“有效页集合 + 当前页”，生成/验证 `readRangeVersion`。
- 前后端原子切换到 `selections[]`，逐段验证块和偏移；不保留无法验证的文本直传路径。
- 检索只在可读页集合中运行，当前页和显式选区有较高优先级；引用回到真实物理页。
- 补防剧透、跳页不解锁、过期范围、错书/错块/错偏移、跨页选择和引用失败测试。

### WP5：三书验收与收口（3—5 人日）

- 前端、服务端、迁移、导入、构建全量回归。
- 三本书各完成原版/文字模式全链路冒烟。
- 在学校目标 Android 平板或等效真机验证横屏、触摸、内存、长书翻页、PDF 首开和切换速度。
- 用真实模型配置完成选文问答、有效已读跨页问答、后文拒答和引用跳转；密钥、原响应和学生隐私不进入仓库或报告。
- 输出缺陷表、OCR 抽样报告、性能记录和是否扩到 49 本的 Go/No-Go 结论。

## 8. 核心验收场景

1. 在 book-025 第 80 页从原版切到文字再切回，始终停在物理第 80 页；刷新和重新登录仍从同一位置继续。
2. 在文字模式选择一个块内字符范围，问竹娃后服务端重建出的选文与界面一致，引用跳回同一页同一段。
3. 在第 12、13、17 页各选一段，统一提问时三段都按自身页/块/字符范围验证。
4. 学生直接跳到第 100 页后提问：AI 可用当前第 100 页，但不能因此检索 1—99 页中没有有效阅读事实的页面。
5. 学生有效读过第 12、17 页，再到第 20 页提问：可读集合为 `{12,17,20}`，不是 `1...20`。
6. 修改客户端 quote 文本、块 ID、偏移或 `readRangeVersion`，服务端拒绝；不产生无引用书内事实回答。
7. 原版模式没有透明 OCR 错位层；页面排版、插图和页数与源 PDF 一致。
8. OCR 空页、低置信页和疑似错字都有质检结论；未通过质量门禁的书不能发布。
9. book-045 连续翻阅、跳页、切换模式和打开 AI 时无明显内存失控或整书一次性 DOM/PDF 页面渲染。
10. 阅读模式切换不改变有效阅读与护眼的唯一真值，不双写旧统计。

## 9. 工期估算与阶段闸门

三书试点预计 **16—25 人日**。若由两个互不覆盖文件所有权的 Agent/工程师并行，日历时间可缩短，但 WP0、数据库/契约接线和最终验收必须串行收口。

阶段闸门：

1. G0：`book-package/v2`、页码、AI 和逐页覆盖契约冻结。
2. G1：三书 release 全部通过 OCR 质量门禁。
3. G2：book-025 纵向链通过（导入 → 双模式 → 共享进度 → 选文 AI → 引用）。
4. G3：book-001 与 book-045 的低年级/长书差异回归通过。
5. G4：目标平板、真实模型、权限、性能和全量测试通过后，才决定扩到 49 本。
