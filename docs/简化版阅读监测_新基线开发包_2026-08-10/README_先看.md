# 简化版阅读监测：新基线开发包

> 包版本：`reading-monitor-clean-baseline-v1.0`
>
> 生成日期：2026-08-10
>
> 适用对象：准备在“最初正式 v3 交接源码”的干净副本上重新开发的主控 Agent、后端 Agent、前端 Agent和验收 Agent。

## 1. 这个包解决什么问题

此前的阅读行为分析方案包含页面累计、速度比较、待补页面、热点、页面证据和多层教师下钻，已经因工程量过大被正式放弃。

本包只保留已经重新确认的简化业务：

- 每日有效阅读时长；
- 5 分钟打卡与连续打卡；
- 每日是否发生跳读、是否发生回读；
- 上次停留位置；
- 学生每日简报；
- 教师班级打卡率、人均时长、七日趋势和学生详情。

本包面向干净基线，不要求继续承载旧开发工作区中的 `016` 页面事实迁移、E6 待补页草稿或教师四页面族草稿。

## 2. 文档权威顺序

请按以下顺序阅读：

1. `01_最新版需求与上游计划.md`
2. `02_新基线接管与选择性移植指南.md`
3. `03_指标规则与采集上传.md`
4. `04_数据模型与API契约.md`
5. `05_学生端与教师端开发指南.md`
6. `06_测试验收与进度追踪.md`
7. `07_新主控启动提示词.md`

出现冲突时，前序文件优先。下游实现发现上游矛盾时，应先修订对应文档，不能在代码中静默选择一种解释。

旧版阅读行为分析计划、旧 API 契约、旧教师指南、旧待补页面指南和冻结快照只能作为历史背景，不得补充本包没有的功能。

## 3. 新基线定义

新基线必须满足：

- 来源是最初交接的正式 v3 React/Vite + Node/SQLite 工程；
- 不是早期 Flutter 学生端或旧 APK 工程；
- 没有混入旧复杂阅读分析的未提交文件；
- 可以运行交接版本原有的服务端、前端和构建测试；
- 在任何开发前保存基线提交或等价的只读校验信息。

如果新基线已经存在旧 `016_reading_behavior_facts.sql`、学生 E6、教师 E6 或 `src/student/reading-telemetry/**`，必须先确认它是否真的是干净原版，不能继续假设。

## 4. 开工顺序

1. 核对新基线身份和测试基线。
2. 根据 `02` 形成移植决议；默认不移植旧成果。
3. 按 `03` 和 `04` 冻结指标、上传、数据库和 API。
4. 先完成后端会话摘要、每日汇总和查询。
5. 再接入阅读器客户端。
6. 最后完成学生每日简报和教师阅读统计。
7. 按 `06` 做联合验收。

本轮不封装 APK，不迁移 PostgreSQL，不恢复旧复杂方案。

## 5. Git 和文件保护

- 不得把旧开发目录整体复制到新基线。
- 选择性移植必须按文件和测试逐项进行。
- 不修改已经执行的迁移。
- 不执行破坏性重置或清理未识别文件。
- 未经用户授权，不暂存、提交、推送或切换分支。
- 不建立“新接口失败就回到旧接口”的静默兼容路径。

## 6. 完成定义

只有当以下条件同时满足，才视为本包任务完成：

- 学生阅读时长、打卡、连续天数和鼓励文案正确；
- 跳读、回读只保留每日布尔值；
- 教师能看到班级和学生数据但没有排名；
- 直接跳到最后一页不会自动标记读完；
- 重复上传不重复计时；
- 学生接口不泄露上周具体差值；
- 不同学校数据隔离；
- 旧热点、待补页、速度和页面证据没有进入新基线；
- 全量测试、构建和关键浏览器流程通过。
