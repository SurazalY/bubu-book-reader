# 学生端与教师端开发指南

> 文档版本：`clean-baseline-ui-v1.0`
>
> 原则：沿用正式 v3 设计系统，不重做全站视觉，不新增独立视觉轨。

## 1. 共通原则

- 使用现有玻璃卡片、低饱和配色、圆角、字体层级和响应式骨架。
- 不使用惩罚性红色表达未打卡、跳读或回读。
- 不显示排名、名次、百分位、最快、最慢、最好或最差。
- 加载、空数据、权限拒绝和网络错误必须真实区分。
- 不使用 fixture 或默认值填充生产失败状态。
- 时间数据以服务端为准，页面不得重新计算另一套业务口径。

## 2. 学生每日简报

### 2.1 位置

放在学生首页主要内容区顶部。它是一张持续更新的卡片，不新增底栏入口、独立路由、弹窗任务或每日永久消息。

### 2.2 信息结构

```text
┌──────────────────────────────────────────┐
│ 今日阅读                       数据已更新 │
│                                          │
│ 12 分钟                    今日打卡已完成 │
│ [──────── 5分钟进度/完成状态 ────────]   │
│ 今天的阅读积累很不错，继续保持！          │
│ 已连续阅读 6 天                           │
│                                          │
│ 继续阅读《书名》                          │
│ 上次停留在第 86 页              [继续阅读]│
└──────────────────────────────────────────┘
```

### 2.3 字段映射

| UI | API 字段 |
| --- | --- |
| 今日时长 | `todayEffectiveReadingSeconds` |
| 打卡状态 | `checkIn.checked` |
| 进度 | `thresholdSeconds - remainingSeconds` |
| 连续天数 | `streakDays` |
| 鼓励文案 | `comparisonState`映射 |
| 书名和位置 | `lastReading` |
| 更新时间 | `dataUpdatedAt` |

### 2.4 鼓励文案

建议固定映射，不在客户端读取具体上周差值：

| 状态 | 文案方向 | 示例 |
| --- | --- | --- |
| `more` | 表扬 | 今天的阅读积累很不错，继续保持！ |
| `close` | 稳定 | 今天也在稳定积累，保持这个节奏吧。 |
| `growth_space` | 委婉鼓励 | 今天已经完成了一些阅读，再读一会儿会更充实。 |
| `no_baseline` | 开始积累 | 每一次阅读都在积累，今天也继续吧。 |

不得出现“比上周少”“下降”“退步”“未完成任务”等文字。

### 2.5 5 分钟进度

- 未达到 5 分钟：显示正向进度和剩余时间。
- 达到后：显示完成状态，不再强调超出多少。
- 今日 0 秒：可以显示“从今天开始新的阅读积累吧”，不显示失败图标。
- 连续天数为 0：不显示“连续 0 天”，显示开始新记录的鼓励文字。

### 2.6 继续阅读

- `lastReading`存在时显示书名和上次停留页码。
- 点击后使用现有书籍/阅读器路由打开正确书籍版本，并定位到 `lastPageNo`。
- 不显示“完成百分比”。
- `lastReading`为 null 时显示进入书架的按钮，不能填充演示书籍。

### 2.7 数据刷新

- 学生首页首次进入时查询。
- 从阅读器返回首页时立即重新查询。
- 阅读器进入后台或关闭前先触发摘要提交；查询发生在提交确认之后或由状态层明确等待最新确认。
- 不需要在学生首页长期高频轮询。

### 2.8 状态

- `loading`：保留卡片骨架，不能显示 0 分钟假数据。
- `ready`：显示真实内容。
- `error`：显示简短错误和重试按钮。
- `forbidden`：不保留旧成功数据冒充当前结果。
- 无上周基线不是错误，使用 `no_baseline`文案。
- 无最近书籍只影响继续阅读区域，不影响今日统计。

## 3. 教师阅读统计

### 3.1 页面结构

继续使用现有“班级与学生 → 阅读统计”。不新增热点、书籍证据、页面证据或独立学生详情页面。

```text
页面标题 + 班级/统计日 + 更新时间 + 手动刷新

[今日打卡率] [全班人均时长] [跳读人数] [回读人数]

[最近7日打卡率趋势] [最近7日人均时长趋势]

姓名搜索 + 状态筛选

学生列表
  点击学生 → 右侧详情抽屉
```

### 3.2 总览卡片

#### 今日打卡率

显示：

```text
74%
37 / 50 人
```

不显示“打开过但不足 5 分钟”人数。

#### 全班人均有效阅读时长

使用 `perCapitaEffectiveReadingSeconds`，包含零时长学生。界面标题可以写“今日全班人均阅读”。本期不增加长篇口径说明。

#### 跳读和回读人数

只显示人数，不显示次数、页码和负面结论。标签建议为“记录到跳读”“记录到回读”。

### 3.3 七日趋势

- 可以使用简单柱状图或折线图。
- 一张显示打卡率，一张显示人均有效阅读时长。
- 必须显示连续 7 个统计日，零值日期不能消失。
- 不与其他班级比较。
- 图表需有文字或数值替代，不能只靠颜色表达。
- 不引入重量级图表库；优先复用现有组件或用简单 SVG/CSS 实现。

### 3.4 查询和刷新

- 首次进入立即查询。
- 切换班级或统计日立即查询。
- 每 5 分钟重新查询一次。
- 提供手动刷新按钮。
- 页面隐藏时可以暂停轮询，重新可见时立即查询。
- `dataUpdatedAt`按本地可读格式显示“数据更新至 HH:mm”。
- 页面查询不是后台分析任务；无新上传时结果不变。

### 3.5 搜索与筛选

一期一次返回最多约 50 名学生，在前端完成：

- 姓名搜索；
- 全部学生；
- 今日已打卡；
- 今日未打卡；
- 今日发生跳读；
- 今日发生回读。

“今日未打卡”包括 0～299 秒的全部学生，不区分是否打开过应用。

如果 UI 允许组合筛选，必须明确 AND/OR 语义；第一版建议使用单一状态筛选，避免复杂组合。

### 3.6 学生列表

默认按规范化姓名和稳定学生 ID 排序。不得按时长、打卡、跳读、回读和差值形成竞争性排序。

建议字段：

- 姓名；
- 今日有效阅读时长；
- 打卡状态；
- 连续天数；
- 跳读是否发生；
- 回读是否发生；
- 最近阅读时间；
- 查看详情动作。

### 3.7 学生详情抽屉

桌面端从右侧打开；窄屏占满主要视口，但仍属于同一阅读统计页面，不新增路由。

内容顺序：

1. 学生姓名和今日打卡状态；
2. 今日有效时长、连续天数；
3. 上周总时长、上周自然日日均、今日截至目前的具体差值；
4. 最近 7 日简单柱状图或列表；
5. 今日跳读、回读布尔事实；
6. 最近阅读书籍和上次停留位置。

教师端可以显示：

> 截至目前，今日较上周日均少 1 分钟

但不得自动解释为退步或不认真。

关闭抽屉后必须保留原搜索、筛选和滚动位置。

### 3.8 教师页面状态

- 加载：总览骨架和列表骨架。
- 空班级：明确无有效学生。
- 无阅读数据：显示真实 0 和空趋势，不伪造演示数据。
- 权限拒绝：清空受保护数据并显示权限状态。
- 网络错误：显示重试，不能继续显示旧成功并标为最新。
- 轮询失败：明确数据未刷新，可保留旧数据显示时间，但不得更新 `dataUpdatedAt`或假装成功。

## 4. 阅读进度相关页面改造

需要搜索并改造所有以下语义：

- `progress.percent`；
- `finished`；
- “已读完”；
- “全部读到最后一页”；
- 根据最后页码统计读完书籍。

允许继续显示：

- 上次停留页；
- 当前阅读位置；
- 继续阅读。

如果其他既有业务确实需要“学生主动确认读完”，必须另立明确规则，不能继续由最后页码推断。

## 5. 可访问性与响应式

- 所有按钮满足触控目标尺寸。
- 进度条具有文本说明和 ARIA 值。
- 图表提供日期和数值文本。
- 抽屉支持 Escape 关闭、焦点限制和关闭后焦点恢复。
- 1024×768 平板下学生卡片和教师抽屉不出现横向溢出。
- 颜色不能成为打卡和行为状态的唯一传达方式。
