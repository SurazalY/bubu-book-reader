# 新基线接管与选择性移植指南

> 文档版本：`clean-baseline-intake-v1.0`

## 1. 目的

本文件用于确保新开发从最初正式 v3 的干净源码出发，同时避免丢失旧开发工作中真正有价值、已经验证的通用能力。

新基线不是“把旧目录清空”，也不是“把旧目录整体复制过来”。正确方式是保留旧目录作为只读参考，在干净基线上逐项实现或选择性移植。

## 2. 接管前检查

### 2.1 身份检查

新基线应当是：

- React/Vite 学生端和教师端；
- Node/SQLite 服务端；
- 正式 v3 的账号、工作空间、书籍、阅读器和统计基础；
- 不以早期 Flutter、旧 APK 或静态前端壳作为开发源。

记录以下证据：

- 绝对路径；
- 当前分支和 HEAD；
- `git status --short --branch`；
- 迁移文件列表和迁移账本；
- Node 与依赖版本；
- 服务端、前端和构建基线结果。

### 2.2 污染检查

重点确认是否已经存在：

- `016_reading_behavior_facts.sql`；
- `src/student/reading-telemetry/**`；
- `src/api/studentReadingAnalytics.js`；
- `src/api/consoleReadingAnalytics.js`；
- 待补页面、热点、页面证据相关组件和测试；
- 旧阅读分析未跟踪文件。

如果存在，先判断来源，不能继续把目录称为干净基线。

## 3. 迁移原则

- 读取新基线实际迁移账本，使用“当前下一个未占用迁移编号”。
- 不为了填补编号空缺而复制旧 `016`。
- 如果干净基线最高迁移是 `042`，简化版应从 `043` 开始，而不是占用历史工作区的 `016`。
- 不修改已经执行的迁移。
- 新迁移必须支持全新数据库顺序执行、已有干净数据库前向执行和重复启动校验。
- 在 SQLite 上实现时仍应避免没有必要的 SQLite 专属业务语义，为未来 PostgreSQL 留出空间。

## 4. 选择性移植矩阵

| 旧成果 | 默认决定 | 移植条件 |
| --- | --- | --- |
| E1 稳定阅读视图、访问和停留状态机 | 可选择性移植 | 必须能裁剪为单页/双页视图、连续停留、前后台和交互切段；不得继续输出页面证据 |
| E1 双时钟和确定性事实构造辅助 | 可参考或移植 | 只保留累计摘要需要的时间正确性，不复制旧 page fact DTO |
| E2 IndexedDB 账号隔离、原子序号和幂等批次 | 可选择性移植 | 改为保存会话累计摘要；删除旧页面事实 schema 前必须有新测试 |
| E2 崩溃恢复和 pending 队列基础 | 可选择性移植 | 本期只保证在线会话短时失败恢复，不得扩展为正式离线阅读 |
| G1 统计日、有效时长、回读边界纯函数 | 可选择性移植 | 函数与新 `03` 完全一致且有独立测试 |
| G1 速度、热点、待补和页面分配函数 | 不移植 | 业务已经取消 |
| 旧 `016` 页面访问、停留片段和页面分配表 | 不移植 | 新基线使用新的最小迁移 |
| `4b8f478` 旧删除作业框架 | 只读参考 | 只有新数据模型需要并且通过独立复核时才重新实现，不直接拷贝 |
| 学生 E6 待补页 API/adapter/hook | 不移植 | 业务已经取消 |
| 教师 E6 四页面族 API/adapter/hook | 不移植 | 新教师端只有一个主页面和详情抽屉 |
| 旧视觉截图和热点 IA | 不移植 | 只保留历史归档，不作为验收依据 |
| 旧 API v1.1 与教师指南 | 不移植 | 以本包 `04`、`05` 为准 |

## 5. 移植工作方法

每个准备移植的能力必须形成一条记录：

```text
来源文件：
来源提交或哈希：
对应新需求：
准备保留的函数或模块：
明确删除的旧输出：
需要补充的测试：
目标文件：
验证结果：
```

移植优先采用小范围补丁或按新契约重新实现，不整体复制目录。

## 6. 新基线建议文件方向

具体命名由主控结合源码确定，但职责应保持：

- 阅读器运行时：管理稳定视图、连续停留、行为布尔和累计摘要；
- 本地待确认区：只保存会话摘要、修订和幂等信息；
- 服务端 reading 域：接收摘要、维护会话和每日书籍汇总；
- 统计查询：派生学生简报和教师班级结果；
- 学生状态层：只消费本人简报；
- 教师状态层：只消费班级快照，筛选在 50 人范围内可前端完成。

## 7. 明确禁止的接管方式

- 用旧目录覆盖新基线；
- 复制旧 `016` 后再“暂时不用”；
- 同时保留旧逐页写入和新累计摘要双写；
- 新接口失败时回退读取旧分析接口；
- 为了让旧 E6 测试通过而恢复待补页或热点字段；
- 降低权限、幂等、迁移或删除测试断言；
- 把未验收文件标为已完成。

## 8. 基线门禁

以下条件满足后才能进入生产代码开发：

- 新基线身份和测试结果已记录；
- 新迁移编号已经根据实际基线确认；
- 所有旧成果都有明确的移植或不移植结论；
- `03`～`06`完成交叉检查；
- 没有未解释的旧阅读分析文件；
- 主控明确后端、客户端和页面的唯一写入者。
