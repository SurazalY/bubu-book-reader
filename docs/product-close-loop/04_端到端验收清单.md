# 04 端到端验收清单

最终验收必须在真实运行环境执行（本机启动前后端 + bootstrap 演示账号 + 真实导入的 49 本书），不能只靠单元测试或代码走读。每条验收项按五级状态记录：

- **L1 代码已实现**（走读确认）
- **L2 自动测试通过**（对应测试存在且绿）
- **L3 实际运行通过**（真实启动、真实操作验证）
- **L4 真实书目验证通过**（用导入的 49 本真书验证，而非 fixture）
- **L5 因环境或凭据尚未验证**（如实标注原因）

L3/L4 需要证据（截图、SQL 查询输出、network 记录），存 `docs/product-close-loop/evidence/`。

## E. 阅读计时与统计

### E 节 Phase 6 前置说明（2026-08-17 主控裁决）

**验收范围**：Phase 6 按**单设备、单浏览器标签**执行（与下文 F3 一致）。**不验收**跨设备/多设备租约冲突（D-12）；该项记为已知风险，详见 `evidence/phase2/defect-ledger.md` 第十三节。

**增量口径（必读）**：业务库当日汇总已被 D-15 僵尸会话污染约 3.24 分钟（台账第十二节第 6 条）。**清理坏数据不在 Phase 6 范围内。** E1、E2、E5、E9、E11 等涉及时长的项，验收时：

1. 操作前记录 baseline（`GET /reading/statistics/self` 今日秒数，或详情页「有效阅读时间」分钟数）；
2. 前台连续阅读 ≥1 分钟（E11 为 ≥5 分钟）；
3. 断言**增量**约等于实际阅读墙钟（允许 ±15 秒调度余量），**不与历史绝对总数对照**。

**必须如实记录的已知偏差**（验收矩阵「备注」栏须引用编号，不得隐瞒）：

| 编号 | 偏差 | 备注写法示例 |
|---|---|---|
| K-01 | 双页对开成对记账，逐页 ms 之和 ≠ 日汇总 | 设计如此，见台账 §12 |
| K-02 | 当日汇总含约 3.24 分钟历史污染 | 增量验收，见台账 §12.6 |
| K-03 | `valid_reading_seconds` 恒 0 | 旧路径遗留，E14 覆盖 |
| K-04 | 详情页累计 vs 主页当日口径不同 | 不可互相对照，见台账 §12.4 |
| K-05 | D-12 跨设备静默丢时长 | 已知风险，本 Phase 不验 |
| K-06 | 阅读器直回主页时书架进度可能 stale | D-16 遗留，当前路径不经此 |

完整证据与推断区分见 `docs/product-close-loop/evidence/phase2/defect-ledger.md` 第十一至十三节。
