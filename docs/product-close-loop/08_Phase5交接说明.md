## 二、三条任务的落点与完成标准

原始定义见 `03_实施任务清单.md` §Phase 5。以下是补充的落点与坑。

### T5.3 跳页参数修复（最小，建议先派）

`src/student/pages/Highlights.jsx` 用的查询参数是 `?page=`，而阅读器的 `resolveReaderLocation` 认的是 `?pageNo=`，导致**从摘录跳转会落到错误的页**。改成 `?pageNo=`，并**全局搜索其他 `?page=` 误用处**一并修。要有测试覆盖。

### T5.2 空白页占位

文字模式下，对"导入时标记为空页"的页（无 block、normalized 文本为空）渲染明确的空白页占位（如"本页为空白页"），**与网络/加载错误状态视觉上要能区分**。PDF 模式不变，空白页不影响翻页与页号。更新前端契约测试。

**可验证的真实数据**：`book-001`《和大人一起读·儿童歌谣》98 页里有 10 个空白页（如 page-0002、page-0003）。

**这条有一个必须传达给实施方的约束**：D-06 之后会改动同一块渲染代码的**布局模型**（见第三节）。所以空白页分支要写成**结构独立的早返回/独立渲染分支**，不要把它和固定画布、`transform: scale`、`overflow: hidden` 这套布局假设绑在一起。否则 D-06 落地时要推翻重做。

### T5.4 学生端退出登录

个人中心 `/student/me` 加"退出登录"入口 → 调已有的 `POST /auth/logout` → 跳 `/student/login`。

**不要在 logout 里加任何计时处理。** 从 Reader 返回再退出的路径上，计时会话已由现有逻辑按 `reader_close` 收尾。**阅读计时是项目冻结契约**（表、schema、指纹算法、租约 TTL、续租路由一律不动），它在 D-11 / D-15 / D-17 三次复发过，是本项目最大的雷区。

**一个与 Phase 8 的轻度重叠**：Phase 8 要在学生端显示"我在哪个班"，很可能也落在 `/student/me`。冲突是文本级的（两块不相关的 UI 加在同一页），不构成阻塞，但请在本阶段完成后于本文件末尾记一行，方便 Phase 8 知道该页已被改过。

### T5.5 印刷页标签检查（验证任务，放进验收窗口）

本批书 `printedPageLabel` 全为 null，确认底栏"第 X 页 / 共 Y 页"的物理页语义正常。**预期无需改动，异常才修。**

## 三、等用户回来才能做的事

### D-06：文字模式长页正文被裁掉，且被裁内容完全不可达

**这是内容丢失，不是显示瑕疵**，已定性为应修，影响 49 本里所有文字较多的页。

根因（已查清，不必重查）：文字页是固定 468×636 的设计画布，窗口变化只做 `transform: scale`、**禁止重排**（`src/student/components/BookPage.jsx` 第 6–14 行）。裁切发生在多层且**均无 `overflow-y: auto`**：`.student-page-frame` 的 `overflow: hidden`（`src/index.css` 1228–1230）、`.student-page-body` 的 `min-height:0; overflow: hidden`（同文件 1308–1314）。页内不能滚、不能展开、翻页是换到另一张物理页。切回原版 PDF 能看全文，但那是换模式，不构成文字模式的阅读能力。

**修法需用户裁决**，三个方向：页内滚动 / 自动缩小字号以适配 / 增加展开。**不要自行选择。**

**为什么它和 T5.2 都在同一处，却建议 T5.2 先做**：T5.2 处理"没有内容时显示什么"，D-06 处理"内容太多时怎么让用户读到"，两者互补而非冲突；而 T5.2 小且独立，不该被一个产品决策卡住。代价是 D-06 落地时可能要微调空白页分支——所以上面要求它结构独立。

### T5.1 模式持久化

冻结中。解冻时机由用户定。若在 Phase 8 之前做，需单独占一个稳定窗口（要新表 + 重启后端 + 验收）；若在 Phase 8 之后做，需与 Phase 8 的迁移号协调。

## 六、继承的硬规则与红线

**逐条都是用户定的红线，违反即事故。**

- **主控不写业务代码、不跑测试构建、不直接探索代码库。** 一切实现派子 agent。主控可读文档、做最小抽查。
- **不开浏览器**，不使用任何浏览器工具。浏览器操作全部由用户本人执行。本项目曾因 agent 开的标签页脱管、持续占用业务资源而堵死近三小时。
- **不得宣称"验收通过"**，必须有真实运行证据。五级状态：代码已实现 / 自动测试通过 / 实际运行通过 / 真实书目验证通过 / 因环境或凭据尚未验证。
- **阅读计时是冻结契约**：表、schema、指纹算法、租约 TTL、续租路由一律不动。
- **不得向业务数据库 `server/data/readmate.sqlite` 手工写入。** 测试一律用临时库（`mkdtempSync`）。
- **决策必须留痕**。
- **除第五节授权的那一次提交外，不得做其它 git 写操作**，尤其不得 `git checkout` / `reset` / `stash` / `clean` / `restore`——工作区里堆着多个 agent 的未提交成果，清掉找不回来。

## 八、派子 agent 的经验（Phase 4 实打实的教训，请照用）

- **每个 prompt 里必须重申完整禁令**，尤其"不得 `git checkout`/`reset`/`stash`/`clean`"。
- **要求每份报告分「实测」与「推断」两栏**。这一条在 Phase 4 抓出了大量问题，是性价比最高的一条要求。
- **子 agent 会越界做"顺手的清理"**。有一个以"不得出现完成度"为由删掉了既有 UI 里的阅读安排完成率（那是班级管理指标，不是个人阅读进度，且契约限定的是**新增**界面）。已驳回并还原。**硬契约是约束新增的，不是授权在无关范围内做清理。**
- **子 agent 会留下"休眠缺陷"**。D-10 第一版把封面改成 `no-store` 但其余资产类型保留 `max-age=3600`，等于把缺陷改成潜伏态。要求改成 fail-safe 默认后才通过。
- **子 agent 的高危报告也可能是误报**，要自己核。
- **改适配器层字段前必须把消费方引用链查到底**，不能靠组件名和跳转路径推断归属。上一任主控曾误判 `src/components/ui.jsx` 的 `BookCard` 在学生端路径上，复核后发现它只服务旧站演示数据，及时中断了任务。
- 独立验证方（只写测试、不改实现）的测试文件是它的资产，实施方不得随意改动；需要改时逐条授权并记录理由。新增用例放新文件。
