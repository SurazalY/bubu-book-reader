# 02 决策记录与契约边界

本文件记录 2026-08-17 与产品负责人逐项确认的决策（D1–D15），以及执行时必须遵守的契约边界。**执行者不得推翻这些决策**；如发现决策与代码现实冲突且代价重大，停下来向用户报告。

> **Phase 8 覆盖说明（2026-08-18）：** D2“教师可全局发布”、D3“无 grants=全组织可见”及由此派生的学校端发布/可见范围交互只记录 Phase 4 当时口径，已被 `09_Phase8班级管理系统设计与交接.md` 与 `evidence/phase8/decisions.md` P8-07/P8-08 覆盖。现行口径是：全局书库只由技术团队管理；教师只管理本人班级书架；无 grants=不可见。其余冻结契约继续有效。

## A. 已确认决策

### D1 导入质检闸门：新增"可信 OCR"验收模式
现有 `import:book-package-v2` 与 `publishBook()` 强制 `quality.status='passed'` + 人工复核通过（上轮试点冻结契约，也是当时 No-Go 的原因）。本轮**授权修改导入链**：
- 新增显式的包质量状态值（建议 `trusted-baseline`），语义为"OCR 按新基线视为可信输入，未做人工逐页质检"。
- 导入器增加显式开关（建议 `--accept-trusted`）：带开关时接受 `trusted-baseline` 包；**所有结构校验保留**（manifest 完整性、文件哈希、PDF 页数与 pageCount 一致、块偏移合法、幂等重导）。不带开关时行为与现在完全一致（`passed` 仍要求人工复核），保证旧路径不回归。
- 数据库 `book_versions.package_quality_status` 写入真实状态（`trusted-baseline`），并在 `audit_events` 记录豁免事由，做到留痕可追溯。
- `publishBook()` 同步放宽为接受 `passed` 或 `trusted-baseline`。
- **禁止**伪造 `passed` 状态或伪造人工复核记录。

### D2 发布权归属：教师可发布
新增发布管理 HTTP API + 教师端 UI，并给教师角色（`teacher`/`class_teacher`）授予发布/下架权限（改 `server/domains/identity/permissions.js` 的动作表）。校长与平台角色原有权限不变。

### D3 可见范围粒度：班级级
启用 `book_access_grants`（`grantee_type='class'`）实现班级级可见范围。语义：
- 某书版本**没有任何 grants 行** → 全组织可见（默认，与现状一致）。
- 有 grants 行 → 仅授权班级的**学生**可见（书架列表、页面 API、资产 API、AI 引用一致过滤）。
- 教师/管理角色在控制台书库始终可见本组织全部书（否则无法管理）。
- 单个学生粒度本期不做。

### D4 导入后默认状态：published
49 本导入即发布（作为系统默认书单全员可见），教师/管理可再下架或收窄班级范围。

### D5 book-031：已补齐
用户已补齐缺失的 10 页 OCR。已复核：`book-031/pages` 现有 160 txt + 1 blank = 161 页，与 PDF 页数一致。按普通书导入，无特殊处理；打包时仍要断言页号连续。

### D6 编目元数据
书名用 `01_现状与资产盘点.md` §5 的人工整理对照表（含"列那狐的故事"纠错）；封面由原版 PDF 第 1 页渲染生成（建议 PyMuPDF，JPEG，宽约 600px）；作者本期留空。

### D7 年级分类
年级（1–6）落库为编目字段，学生书架与教师书库支持按年级筛选/分组。

### D8 阅读模式持久化
记住学生**每本书**上次使用的模式（original/text），刷新与重新登录后均恢复。实现约束见 §B-3（不得触碰计时摘要契约）。恢复优先级：服务端偏好 → 默认逻辑（有 source_pdf 资产默认 original）。

### D9 AI 验收环境
用户将在最终验收阶段提供真实模型端点凭据（`AI_BASE_URL`/`AI_API_KEY`/`AI_MODEL`，执行时写入 `.env`，不入 Git）。在拿到凭据前，AI 链路各项在报告中标注"因环境或凭据尚未验证"。

### D10 教师端阅读器
不在本期范围。教师端阅读器维持现状（纯文字、无双模式、无计时）。

### D11 学生端退出登录
本期补一个最小的学生端退出登录入口（个人中心 → 调 `POST /auth/logout` → 回 `/student/login`），用于验收"退出登录/重新登录后进度恢复"。

### D12 验收环境

### D13 磁盘

### D14 版权标识
继续使用内部标识（如 `internal-default-catalog` 之类的 usage label），不声称对外版权结论。学生/教师界面不需要展示该标识。

## B. 契约边界（改什么、不改什么）

### B-1 允许且需要修改的
- `server/db/import-book-package-v2.js`（D1：trusted 模式 + 注册封面资产）
- `server/domains/reading/catalog.js`（publishBook 放宽、发布/下架/可见范围领域函数、listBooks 班级过滤）
- `server/http/integration-router.js`（新增发布/可见范围/模式偏好端点）
- `server/domains/identity/permissions.js`（教师加发布权限）
- 新增迁移（当前最大编号 044，新迁移从 045 起）：编目年级字段、模式偏好存储等
- `src/console/pages/teaching/`（发布/可见范围 UI）、`src/student/pages/Shelf.jsx` 与教师书库（年级筛选）
- `src/student/pages/Reader.jsx` 及相关组件（模式恢复、空白页状态）、`src/student/pages/Highlights.jsx`（`?page=` → `?pageNo=` 修复）、学生端个人中心（退出入口）
- `book-parser/pipeline/` 新增 antigravity → v2 打包器及其测试
- 对应的 `tests/server/`、`tests/frontend/` 测试

### B-2 禁止修改/禁止发生的
1. **计时真值模型**：不改 `reading_summary_sessions`/`reading_daily_book_summaries` 表结构，不改 `POST /reading/session-summaries` 的请求 schema 与指纹算法（指纹字段集是冻结的，加字段会破坏所有客户端指纹校验），不改租约 90s TTL 与续租路由。G1 冻结决议 D-01～D-10 全部继续有效。
2. **不新建第二套计时/进度**：PDF 引擎与文字引擎必须共用 `src/student/reading-monitor/**` 的唯一 coordinator 状态机。模式切换不得触发 `book_change`/新会话/新租约；不得把旧 `reading/events/batch` 重新当阅读时长来源（它只喂护眼，有效秒恒 0）。
3. **物理页是唯一页码**：不引入第二套页码坐标；不做字符级坐标映射；块几何保持 audit-only（运行时坐标写 0）。
4. **监测查询 DTO**：`GET /reading/statistics/self` 与 `/scope` 的响应结构不动（学生端不得泄露上周差值/跳读回读；教师端无排名）。
5. **完成度禁令**：任何新 UI 不得出现"已读百分比/完成度/读完标记"；位置只表达"第 X 页 / 共 Y 页"；跳到最后一页不产生读完状态。
6. **资产边界**：书籍二进制不进数据库；storage_key 相对键；公开 `/books/*` 保持 404；PDF 只经受保护资产接口供给（pdfjs 加载已如此，勿破坏）。
7. **OCR 输入只读**：不重新 OCR、不改写 `ocr-antigravity-v1` 下的文件、不做 OCR 质量评审流程。provenance 写入包时不得包含本机绝对路径。
8. **不动 `device-migration-20260815/` 归档**、不动教师端阅读器（D10）、不重做 Reader 视觉（双壳视觉基线：模式切换 UI 已在现有顶栏，沿用）。

### B-3 模式持久化的实现约束（D8 落地规则）
- 新增独立的轻量存储与端点（建议：新表 `reader_mode_preferences`（org/user/book_version_id/mode/updated_at，唯一键 user+book_version）+ `PUT /reading/reader-preference`，写请求带 Idempotency-Key，学生本人权限）。
- 前端在模式切换时 fire-and-forget 上报；打开 Reader 时从书目投影或该端点读取偏好。
- **不得**把 readerMode 塞进计时摘要、`reading_progress` 的写路径或任何冻结 DTO；`GET /books` 投影可以**新增**字段携带偏好（新增字段是允许的，改动/删除已有字段不允许）。

### B-4 班级可见范围的实现约束（D3 落地规则）
- 过滤必须在服务端收口：`listBooks`（学生角色）、`getPage`、`getBookAsset`、AI 消息里的书籍访问校验，四处口径一致——学生对不可见书应表现为"书不存在"（404），不是 403 泄露存在性。
- grants 以 `book_version_id` 为键（表结构如此）；发布管理 UI 操作按书（bookId）操作时，服务端解析到当前版本。
- 教师设置可见范围的 UI 只列出该教师有权限范围内的班级。
- 课堂锁书/阅读安排引用了对某班不可见的书属于边界情况：本期只需保证"设置可见范围时给教师明确提示"，不做级联清理。

## C. 风险与注意事项

| 风险 | 应对 |
|---|---|
| Node 版本不足 22.16 导致 `node:sqlite` 不可用 | Phase 0 首先校验 `node --version` |
| 打包/导入 49 本耗时长（PDF 哈希、pdfjs 数页数） | 打包器与导入循环脚本化、可断点续跑（逐本处理、失败不影响已成功的书；导入器本身幂等） |
| pdfjs-dist 固定 6.2.108，PDF worker 独立打包 | 不升级依赖版本 |
| 中文路径/尾随空格 | 打包器内所有路径按字面处理，加存在性断言；不要 trim 文件名 |
| blank 页（0 字节）与"缺页"的区分 | 打包器要求页号 1..pageCount 连续覆盖（txt 或 blank），缺号直接报错——这是结构检查，不是 OCR 质检 |
| 全量导入后书架首屏 49 本 + 封面 | 封面渲染控制在 ~600px 宽 JPEG；如书架加载明显卡顿记录到报告，不做超范围优化 |
| `GET /books?limit=100` | 49 本够用，不改分页 |
