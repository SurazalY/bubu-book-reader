## 一、前置事实（勘察结论，实施方必须先认清）

以下是本次代码勘察查实的现状。它们不是背景介绍，而是**方案成立的前提**，误读会直接做错。

### 1.1 用户为什么发不出帖子（R1 的病根）

不是权限问题，是两个缺陷叠加：

1. **引文实际是必填，但界面写着「可以不带」。** 前端发布按钮的条件是 `选书 && 引文 && 标题 && 正文` 四者齐全（`src/student/pages/Compose.jsx:40`、`:303`），第二道拦截在 `src/student/state/useCommunity.js:191-193`；后端 HTTP 路径上 `structuredQuote(..., required=true)`（`server/domains/community/index.js:227`，`required` 由 `workspace.scopeType !== undefined` 推出，HTTP 请求恒为 true）。
2. **引文候选列表接错了数据源。** 列表读的是 `reader.highlights`，其真实来源是学生在阅读器里点过「问竹娃」才会攒下的 `aiQuotes`（`src/student/community/CommunityRuntimeContext.jsx:17-24`），**不是**界面文案所说的「收藏的摘录」（`Compose.jsx:182`）。该数据只存在于内存，刷新即清空。

所以学生去阅读器收藏摘录再回来，列表依然为空，按钮永远置灰。阅读器侧也确实没有任何「引用并返回共读社区」的回调（全仓库无 `returnTo` / `fromCompose`）。

**数据库本身允许引文三字段全空**（`server/db/migrations/033_community_multistage_review.sql:23-26` 的 CHECK 是「要么三个都为 NULL，要么三个都有值」），因此放宽门槛不需要改表约束。

### 1.2 学校码是租户定位键，不是装饰（R2 的风险源）

登录查询是学校码与登录名的联合查询，学校码进了 WHERE 条件：

```415:418:server/db/../domains/identity/repository.js
WHERE organizations.school_code = ? COLLATE NOCASE
  AND users.login_name = ? COLLATE NOCASE
```

关键约束差异：

| 字段 | 唯一性 | 定义位置 | 登录是否使用 |
|---|---|---|---|
| `users.username` | **全局**唯一 | `server/db/migrations/000_identity.sql:13` | 否（注册后被写成 UUID） |
| `users.login_name` | **仅组织内**唯一 | `server/db/migrations/047_login_and_class_identity.sql:47-49` | **是**（用户实际输入的「账号」） |
| `users.account_code` | 仅组织内唯一 | `047_login_and_class_identity.sql:51-53` | 否 |

直接删掉学校码而不动唯一性约束，多校场景下会跨校撞车。本轮按**单校**定案（见 2.2）。

### 1.3 系统里的「年级」已经被占用为「入学届」（R4 的最大坑）

`classes.grade_id` 的取值形如 `primary:2023`，由 `computeGradeId` 生成（`server/domains/identity/lifecycle.js:47-49`），语义是**入学届**，也是年级主任工作空间的 `scope_id`，并有数据库触发器强制其等于 `stage:entry_year`（`047_login_and_class_identity.sql:96-151`）。

产品语境里的「三年级」是另一个东西：`computeClassLifecycle(...).currentGrade`（`lifecycle.js:51-70`），按上海时区 9 月 1 日滚动计算，**不落库**。

**本轮所说的年级一律指 `currentGrade`。禁止把 UI 的年级绑到 `grade_id`，禁止新建 grades 表。**

### 1.4 密码是 scrypt 单向哈希，明文不可还原（R3 的约束）

`server/auth/password.js:25-40`，存储格式 `scrypt$cost$r$p$salt$hash`。现有「教师重置」能力只能签发 30 分钟一次性重置码（`server/domains/identity/service.js:1528-1582`），教师看到的是 `rawToken` 而非密码；而学生端「忘记密码」点击后只弹一行文案（`src/student/pages/Login.jsx:147-156`），**根本没有重置码输入框**——这就是用户说的「设计割裂」。消费重置码的接口 `POST /password-resets/:token/consume` 存在且有测试覆盖，但**前端零调用**。

### 1.5 三端目前都没有可用的设置（R6 的起点）

- 学生端 `src/student/pages/Settings.jsx` 存在但**未挂路由**，内容基本是演示壳，且 import 了 `../data/me.js` 演示数据；个人主页的设置入口是 `Entry unavailable` 假按钮（`src/student/pages/Me.jsx:209`）与一句「设置服务端接入中」（`Me.jsx:107-110`）。
- 控制台 `src/console/pages/Me.jsx` 同样未挂路由，其「修改密码」弹窗自己写着「前端壳不实现真实改密」（`:465-468`）。
- 后端**不存在**任何「旧密码换新密码」的接口。`PATCH /users/:userId` 只能改 `displayName` 且需要 `account.manage` 权限（学生没有），**不能**拿来做自助改名。

### 1.6 品牌素材现状（R5）

仓库根目录 `培新图标/`（尚未纳入 git）内有两张白底 JPG：

| 文件 | 尺寸 | 内容 |

| `微信图片_20260819171221.jpg` | 2560 × 957 | **横版组合标志**：图形徽标 + 竖分隔线 +「培新教育」+ 英文口号 Educating heart raising creativity |
| `微信图片_20260819171241.jpg` | 882 × 891 | **纯图形徽标**：开口红环 + 变形 P + 几何 X，无文字 |

主色：品牌红约 `#E31E24`、黑约 `#111111`、分隔灰约 `#BDBDBD`。

三端品牌位目前是内联 SVG（两端各一份 `BrandMark.jsx`），显示「读伴」二字，登录页与控制台侧栏顶部各用一次。

## 二、已定版的产品决策（D 系列）

以下每一条都由产品负责人当面拍板，**实施方不得推翻，也不得"顺手优化"**。

### D-1 部署形态：单校

当前只服务培新一所学校。未来若接入新学校，另行定制，本轮不为多校做兼容设计。

### D-2 数据前提：库内只有演示数据，可清库重建

不需要为存量数据做兼容回填。迁移可以采用「新建约束 + 冲突即失败」的严格写法，不必写容错回填逻辑。但迁移脚本本身仍必须可重复执行、幂等。

### D-3 引用功能：发帖侧彻底消失，底层列保留不写

- 学生发帖流程中**完全没有**引用原文这一步，界面上任何位置不再出现引文选择、引文预览、引文相关文案。
- 数据库三列 `quote_book_id / quote_page / quote_text` **保留但永不再写入**，新帖这三列恒为 NULL。
- 理由：删列会让 D-21 系列守卫测试（防止学生看到无权书目的原文）大面积变红，而本项目纪律禁止靠改测试消红。保留列是风险最低的路径。

### D-4 帖子与书的关联：新增独立 `book_id` 列

现在「这本书的共读内容」完全依赖 `quote_book_id`。引用取消后必须有独立字段承载「我要分享的书」。

### D-5 审核：保留，但学校范围也只需本班老师一审

- 学生发帖后仍是 `submitted`，需老师审核通过才在社区可见。
- **变更点**：原先学校范围帖要走「班级审 → 学校审」两级（`server/domains/community/index.js:175-211` 的 `reviewPlan`）。现改为：不论班级范围还是学校范围，**本班老师审核通过即直接 `approved` 并发布**。
- 发布页与「我的发布」必须清楚显示「已提交，等老师通过 / 已通过 / 未通过」，不能让学生以为发失败了。

### D-6 发布门槛：选书 + 标题 + 正文，三者非空即可

不再有任何第四个必填项。

### D-7 登录：取消学校码，登录名升为全局唯一

- 登录 body 只接受 `{ loginName, password }`。
- `users.login_name` 增加全局唯一索引。
- 注册查重从「组织内查重」改为「全局查重」。

### D-8 重置密码：系统生成简单密码，老师端可持续查看至学生自行修改

- 老师触发重置 → 系统随机生成一个**好念好打的 6 位密码** → 直接返回给老师端展示，老师转告学生。
- 老师**可以随时回来再看**这个密码（不是只显示一次）。
- **一旦学生自己改过密码，明文立即从库中清除**，老师端改为显示「学生已自行修改」。
- 学生用新密码登录后**不强制改密**。
- 旧的重置码机制：后端接口与表**保留不动**，但前端完全不再暴露；教师端签发重置码的 UI 改为新的重置流程。
- 学生端「忘记密码」点击后进入一个说明页，告诉学生找老师要新密码。

### D-9 年级语义：当前年级（一~六年级）

- 唯一计算来源是 `computeClassLifecycle(...).currentGrade`，实施方**不得另写一套 9 月 1 日规则**。
- 学段只有小学，年级取值 1–6，不需要在年级之上再加学段层。
- 注册页与教师选班页采用**严格两步**：必须先选年级，选完才出现该年级的班级列表。不提供「全部年级」选项。

### D-10 校长视图：范围切换器，指标沿用班级口径

- 在现有「阅读统计」页顶部工具条新增「全校 / 年级 / 班级」三档切换器。
- 切换器**仅对 `scopeType === 'school'` 的工作空间显示**；教师端看不到，从而实现「不改权限逻辑」。
- 汇总指标沿用现有班级指标：打卡率、人均有效阅读时长、有跳读人数、有回读人数、在籍学生数。**不新增指标，不做排行榜。**

### D-11 品牌：校徽替换「读伴」，文字改为「培新教育」

- 方形图形徽标（882×891 那张）用于小尺寸场景（控制台侧栏顶部、侧栏收起态）。
- 横版组合标志（2560×957 那张）用于登录页 / 注册页。
- 品牌文字由「读伴」改为「**培新教育**」（注意是"教育"不是"小学"）。
- 落位仅两处：**登录 / 注册页**，以及**控制台左侧栏顶部**。本轮不改 favicon、不改营销站顶栏、不在学生端首页新增品牌条。

### D-12 设置：功能极简，只做真能生效的

三端设置只包含四项，**不做头像库**：

1. 修改密码（旧密码 → 新密码 → 确认新密码）
2. 修改显示名
3. 退出登录（复用现有真实登出）
4. 关于与版本

现有那份七大类的 `Settings.jsx` 演示壳**不复用**，见 D-13。

### D-13 学生端设置沿用现有入口，但页面重写

- 入口位置不变：仍从个人主页那个当前显示「暂未开放」的设置入口进入，只是把它解禁。
- 页面**新写**，不复用 `src/student/pages/Settings.jsx`（它与现网 Context 断裂、依赖演示 fixture、退出登录是假的）。旧文件在本轮一并删除。

### D-14 密码规则：宽松

最少 6 位，不强制大小写与符号。上限沿用现有 1024。

### D-15 交付形式

产出一个文档包（本文 + 台账 + 交接说明），并在台账里给出**一张覆盖全部任务的大表**，保证主控在任意时刻都能看到「下一步是什么、依赖谁、谁在等谁」，不会因为任务包彼此独立而丢失全局信息。

### R3 · 教师重置密码可见

#### 3.3.1 数据库

新增表（迁移编号顺延）：

```sql
CREATE TABLE issued_temp_passwords (
  id TEXT PRIMARY KEY,
  organization_id TEXT NOT NULL,
  target_user_id TEXT NOT NULL UNIQUE,
  plaintext TEXT NOT NULL,
  issued_by_user_id TEXT NOT NULL,
  issued_workspace_id TEXT NOT NULL,
  issued_at TEXT NOT NULL,
  version INTEGER NOT NULL DEFAULT 1
);
```

### R6 · 三端设置与自助改密

#### 3.6.1 后端

新增两个接口，**必须挂在 identity router，且是 session-only**（只要 cookie，不要 `X-Workspace-Id`）。理由：学生可能没有任何工作空间，控制台用户可能在切换工作空间，设置功能不该被工作空间绑架。参照模板是 `POST /onboarding/enrollment-requests`（`server/domains/identity/index.js:304-324`）。

| 接口 | body | 行为 |
|---|---|---|

## 五、验收总纲

本轮全部完成后，必须能连续跑通下列真人路径（在演示库上人工走一遍，截图存 `docs/product-close-loop/evidence/phase9/`）：

1. 学生只输账号密码即可登录（登录页无学校码字段）。
2. 学生在共读社区选一本书、写标题与正文，点发布**成功**；「我的发布」显示「等老师通过」；老师在教师端通过后，帖子出现在社区。学校范围帖同样只需本班老师一次通过。
3. 学生忘记密码 → 老师在教师端点重置 → 老师界面看到一串 6 位密码 → 学生用它登录成功。
4. 学生进个人主页 → 设置 → 输旧密码与两次新密码 → 修改成功且当前会话未被踢出；老师端该学生的临时密码显示为「已自行修改」。
5. 学生注册页先选「三年级」再选班级；教师注册与「管理任教班级」同样是两步。
6. 校长在阅读统计页把范围切到「全校」与「三年级」，看到汇总数字；教师在同一页看不到切换器，且直接构造请求会被拒。
7. 登录页与控制台侧栏显示培新校徽与「培新教育」字样，在半透明卡片上无白色方块。
8. `npm run test:frontend` 与 `npm run test:server` 全绿。
