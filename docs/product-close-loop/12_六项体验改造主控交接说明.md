## 二、开工前必须知道的四件事

这四件事是勘察查实的，不是推测。误判其中任何一条都会做错方向。

**第一，用户发不出帖子不是权限问题，是两个缺陷叠加。** 界面文案写「原文可以不带」，但前端按钮条件和后端校验都把它当必填（`src/student/pages/Compose.jsx:40`、`server/domains/community/index.js:227`）；而且引文候选列表接错了数据源——读的是「问竹娃」攒下的内存数据而非用户以为的「收藏摘录」（`src/student/community/CommunityRuntimeContext.jsx:17-24`），所以列表永远是空的。这是本轮最典型的「不诚实 UI」，也是全局禁令第 7 条的由来。

**第二，学校码是登录 SQL 的 WHERE 条件，不是装饰。** `login_name` 目前只在组织内唯一。直接删字段而不升级唯一性约束，多校下会撞车。本轮已按单校定案，用全局唯一索引解决。

**第三，系统里的「年级」已被占用为「入学届」。** `classes.grade_id` 取值形如 `primary:2023`，是年级主任工作空间的 scope，还有数据库触发器强制。产品说的「三年级」是另一个东西：`computeClassLifecycle(...).currentGrade`，按 9 月 1 日滚动、不落库。**这是本轮最容易做错的地方**，台账里为它专门设了两条守卫。

**第四，密码是 scrypt 单向哈希，明文不可还原。** 产品要「老师随时能看到学生密码」，只能靠额外存一份临时密码明文。契约把这件事严格限定在一张表、一种来源（教师签发的临时密码）、一个生命周期（学生自改即删）。

## 三、派工纪律

### 3.1 模型选择

遵循 `.cursor/rules/subagent-model-selection.mdc`，这里复述要点：

- **派子 agent 时必须显式指定模型**，该参数可选，漏填会落到默认模型上，本项目已因此出错两次。
- **默认一律用 grok**，当前环境可用的是 `cursor-grok-4.6-xhigh`。派工前先确认当前环境的可用列表，历史文档里出现的 `cursor-grok-4.6-high-fast`、`cursor-grok-4.6-xhigh-fast` 等名称可能已不存在。
- **`composer-2.5-fast` 永远不启用。**
- **opus 只在用户当场明确指定时才用。**
- 不要为省钱把小任务降到更弱的档，grok 的实际成本低于 gemini，降档没有收益。

**本轮所有任务，包括被早期文档标为「高风险设计类」的那些，一律用 grok。** 早期文档（`03_实施任务清单.md`、`05_主控交接说明.md`）里「须用 opus」的要求已于 2026-08-18 被推翻。风险靠机制控制，不靠模型档位：本轮的做法就是把设计决策提前写死进 `10_...契约.md`，让子 agent 拿到的是执行任务而非设计任务。

### 3.2 守卫与实现必须由不同 agent 完成

这是本项目的实证结论，不是形式主义。Phase 4 最危险的越权缺陷（F-1，越权覆盖全组织授权）是独立的对抗式守卫 agent 攻出来的，写实现的 agent 自己没发现、主控抽查也没发现。D-10 那次子 agent 留下一个默认分支把已修缺陷改成休眠状态，抓住它的是人读源码。两次都不是模型档位能解决的问题。

所以对每一对任务：

1. 先派守卫 agent，它**只写测试不写实现**。跑起来应当是红的。要求它在报告里说明每条测试红在哪、红的原因是「功能未实现」还是「测试自己写错了」。
2. 再派实现 agent，简报里**明确写死**：不得修改守卫 agent 新增的任何测试文件。
3. 实现完成后守卫应全绿。**仍红一律按实现越界处理，回退重做，不许改测试消红。**

唯一例外是台账里每个任务简报的「授权同步更新的既有测试」小节——那是契约变更的必然结果，已精确到文件与行号。**清单之外的任何测试改动都视为越界。**

### 3.3 保护你自己的上下文

不要亲自读大段源码。所有代码勘察、跑测试、查文件的工作都派子 agent 做，你只读它们的报告。本轮的六份勘察报告就是这么产出的，主控全程没有直接读过一行业务代码。

### 3.5 抽查纪律

预算花在独立守卫与抽查上，回报高于花在模型档位上。每个实现任务完成后，至少做这三项抽查：

1. **看 diff 里有没有测试文件的改动。** 出现在授权清单之外的，直接打回。
2. **搜索本次 diff 里的默认分支与兜底逻辑。** D-10 的教训：子 agent 曾留下一个默认分支，把已修缺陷改成休眠状态，测试照样全绿。重点看 `else`、`?? `、`|| ` 后面的兜底值是不是把校验绕过去了。
3. **确认 `permissions.js` 与 `scopeAllows` 未被修改。** 本轮全局禁令第 1 条。

## 四、推荐的派工节奏

台账第一节的大表是权威版本，这里只说节奏判断。

**先开 T2（登录去学校码）。** 它会改动所有 HTTP 测试共用的登录 helper，越晚做与其他任务的冲突面越大。T1（共读社区）与它完全无关，可以同时开第二条线——而且 T1 是产品负责人当前最痛的点。

**T5-0（校徽素材预处理）现在就可以交出去。** 它是人工任务，不占 agent 资源，但会卡住 T5-1。越早开始越好。

**T6 与 T3 是串的。** T6-2 实现自助改密时要预留「清除临时密码明文」的钩子，T3-2 再把钩子接上。派 T6-2 时务必强调这一点，并要求它在报告里指出锚点的确切位置。

**T4 可以与 W2 并行**，它和身份链路没有交集。但 T4-3 与 T4-4 都要等 T4-2 的接口字段就位。

**迁移编号已预分配**：051 归 T2-2，052 归 T1-2，053 归 T3-2。任何任务不得占用不属于自己的号。第一个动手的 agent 需先确认 `server/db/migrations/` 的实际最大编号，以及当前工作区里 `server/db/migrate.js` 那笔未提交改动是什么。

## 五、遗留与后续

以下事项**本轮明确不做**，但已识别，不要在实施中顺手做掉，也不要遗忘：

| 事项 | 说明 |
|---|---|
| 帖子编辑与撤回 | 后端没有更新接口，现有「修改」按钮会再插一条新记录。本轮直接移除入口，真编辑另立任务 |
| 帖子草稿 | 「只存草稿」按钮背后没有任何接口，本轮移除 |
| 学生头像库 | 产品明确本轮不做 |
| favicon 与营销站品牌 | 本轮不动 |
| 护眼管理的年级筛选 | 列为选做 T4-5 |
| 多校支持 | 按单校定案。将来接入新学校时，全局唯一的 `login_name` 需要重新评估 |
| 学生端个人主页的「学校」「班级」字段 | 勘察发现这两个字段在 `GET /session` 里根本不下发，线上是空的（`src/adapters/student.js:33-40`）。本轮不修，但它是一个真实缺陷，建议后续单独立项 |
| `src/console/data/nav.js` 与 `fixtures/` 遗留演示树 | 与现行 `state/navigation.js` 并存且不一致，是持续的误导源。建议后续做一次清理 |
