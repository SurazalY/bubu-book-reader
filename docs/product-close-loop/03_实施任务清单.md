# 03 实施任务清单

按 Phase 顺序执行。每个 Phase 结束时：跑质量门（`npm run test:server` + `npm run test:frontend` + `npm run build`），全绿后 commit 检查点，再进入下一 Phase。任务编号用于报告中引用。

- **T0.2 迁移与启动冒烟**：删除/备用一个临时 `DATABASE_PATH` 启动 `npm run server`，确认迁移 000–044 全部自动应用、`GET /api/v1/health` 正常。
- **T0.3 演示环境就绪**：设置 `INTERNAL_DEMO_PASSWORD`（记录在本地，不入 Git），跑 `npm run bootstrap:internal`；用校长、教师、学生账号分别登录一次确认可用；记录三类账号的 actor-id 与 workspace-id（导入和验收要用）。
- **T0.4 建工作分支** `feat/product-close-loop`。

完成标准：三项质量门绿；三类账号能登录；记录下导入所需的 actor/workspace id。

## Phase 1 编目、打包器与导入链改造（对应决策 D1/D6/D7/D14）

- **T1.1 编目文件**：新建 `book-parser/catalog-default-49.json`：每本书 `bookId`、`title`（按 01 文档 §5 对照表）、`grade`（1–6）、`versionId`（建议 `<bookId>-trusted-v1`）、PDF 相对路径（从 source.json 解析，兼容 `sourcePdf`/`sourcePath`/`source.path` 别名）、`pageCount`。写一个小脚本生成并人工核对 49 行。
- **T1.2 trusted 打包器**：新建 `book-parser/pipeline/build_trusted_package_v2.py`（Python，复用现有 `book-parser/requirements.txt` 环境，封面渲染用 PyMuPDF）。输入：编目行 + `ocr-antigravity-v1` 的 pages 目录 + 源 PDF。输出：符合 book-package/v2 目录结构的包，要点：
  - 结构断言：页号 1..pageCount 连续覆盖（每页恰好一个 `.txt` 或 `.blank`），PDF 存在且 SHA-256 记录；断言失败即报错退出（结构检查，非 OCR 质检）。
  - `content/pages.json`：每页 `rawText` = `normalizedText` = txt 原文（UTF-8）；`.blank` 页文本为空串；分块：按空行分段，每段一个 block，`blockKey` 形如 `p0007-b02`，字符偏移基于 normalizedText 精确计算；几何全零 + `usage=audit-only`；`printedPageLabel` 全部显式 `null`。
  - `content/corrections.json`：空账本。
  - `manifest.json`：`quality.status='trusted-baseline'`（含说明字段记录"OCR trusted per baseline 2026-08-17"）；`quality.automatic.emptyPages` 列出所有 blank 页号；rights 用内部标识（D14）；封面条目指向 `assets/cover.jpg`（PDF 第 1 页渲染，JPEG，宽约 600px）。
  - `provenance/`：指向 antigravity job 的相对标识与文件哈希，**不含本机绝对路径**；prompt 文件不存在时写明确的占位说明文件。
  - 同一输入重复构建应产出字节一致的包（沿用现有确定性构建约定：固定排序、固定时间戳字段来源于输入而非当前时间）。
- **T1.3 打包器测试**：`book-parser/tests/` 新增单测：正常书、含 blank 书、缺页报错、偏移正确性、幂等重建一致。
- **T1.4 导入器 trusted 模式**：改 `server/db/import-book-package-v2.js`：新增 `--accept-trusted` 开关；接受 `quality.status='trusted-baseline'` 且跳过人工复核检查（不带开关时行为不变）；注册 `cover` 资产到 `book_assets`（`asset_type='cover'`）；`book_versions.package_quality_status` 写真实状态；`audit_events` 记录 trusted 豁免。manifest 允许的字段集合按新增内容同步放宽（只增不删）。
- **T1.5 publishBook 放宽**：`server/domains/reading/catalog.js` 中 v2 发布检查接受 `passed` 或 `trusted-baseline`。
- **T1.6 年级字段迁移**：新迁移 `045_book_catalog_grade.sql`（编号以当时目录实际最大号 +1 为准）：`book_catalog_metadata` 增加年级/分类字段；导入器把 grade 写入；`GET /books` 投影（`server/integration/projections.js`）新增 grade 字段。
- **T1.7 服务端测试**：`tests/server/` 新增/扩展：trusted 包被 `--accept-trusted` 接受、无开关拒绝、结构损坏（页缺号/哈希错/PDF 页数不符）仍拒绝、封面资产登记、重复导入幂等、grade 落库与投影。

完成标准：质量门绿；用 fixture 包（小型合成书）全链路单测通过。

## Phase 6 双模式 × 阅读计时联动验收（以验证为主）

计时系统与双模式覆盖均为已验收的存量能力，本 Phase 原则上**只验证、必要时最小修复**。以下硬门禁逐条在真实运行中验证（方法：观察 network 请求 + 查询 SQLite + 学生简报/教师统计页面）：

- **T6.1 模式切换不重复计时**：同一物理页 PDF↔文字来回切换，`reading_summary_sessions` 仍是同一 sessionId、无新会话；`GET /reading/statistics/self` 今日秒数不出现跳变；`reading_summary_page_coverage` 中该页的 originalMs/textMs 按实际停留分别累计。
- **T6.2 切换不丢会话**：切换后继续阅读，累计摘要 revision 连续递增、无 `REVISION_GAP`/`SUMMARY_REGRESSION` 错误。
- **T6.3 可见性/生命周期**：切到其他标签页（hidden）计时停止；回来恢复；关闭 Reader 发出 `reader_close` 收尾摘要；退出登录→重登→进度与今日时长正确。
- **T6.4 幂等**：用开发者工具重放同一摘要请求 → `replayed`，每日汇总不加第二次。
- **T6.5 数据归属**：时长与进度只落在正确的学生×书；开第二本书产生独立会话，无跨书串数据。
- **T6.6 统计与简报**：学生首页每日简报显示真实今日时长/打卡/连续；教师班级统计（`ClassOverview`）能看到该学生数据；打卡阈值 300s 行为正确（读满 5 分钟打卡）。
- **T6.7 旧事件不计时**：确认 `reading/events/batch` 仍只影响护眼，阅读秒数为 0。
- **T6.8 清理脚本**：跑 `npm run maintenance:reading-monitor-cleanup` 无错误。

若发现问题：修复必须遵守 02 文档 B-2 边界（严禁改真值模型），修完回归 T6.1–T6.8。

完成标准：全部硬门禁通过并留证据（SQL 查询结果 + 截图）到 evidence 目录。
