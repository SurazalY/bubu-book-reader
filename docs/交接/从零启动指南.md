# 从零启动指南

面向第一次拿到本仓库源码、需要在空环境把系统跑起来并登录的工程师。按顺序做即可。

本文里的命令已在 Windows + Node 22.17 + npm 11.4 下实际跑通。Linux / macOS 把 PowerShell 的环境变量写法换成 `export` 即可，`node` / `npm` 命令相同。

---

## 1. 环境要求

- **Node.js ≥ 22.16.0**（仓库根目录和 `server/package.json` 的 `engines.node` 都是这个下限。本机验证时为 22.17.0。）
- npm 随 Node 安装即可。验证时为 **npm 11.4.2**。
- 操作系统：Windows / macOS / Linux 均可。本仓库使用 Node 内置 SQLite，不需要单独安装数据库。

检查：

```bash
node -v
npm -v
```

`node -v` 必须是 `v22.16.0` 或更高。

---

## 2. 安装依赖

根目录和 `server/` 各有一份 `package.json`，**两处都要装**。

在仓库根目录执行：

```bash
npm install
npm --prefix server install
```

---

## 3. 配置环境变量

在仓库**根目录**复制模板（不要复制到 `server/` 再启动 `npm run server`，因为这条脚本从根目录拉起，会读根目录的 `.env`）：

```powershell
Copy-Item .env.example .env
```

```bash
cp .env.example .env
```

然后编辑根目录 `.env`。下面按「能不能把服务拉起来」说明。

### 3.1 必须填，否则服务起不来

| 变量 | 作用 | 要求 |
|---|---|---|
| `SESSION_TOKEN_SECRET` | 签发登录 Cookie | **至少 32 个字节**。用普通英文字母、数字时，就是至少 32 个字符。填短了进程会直接退出，提示 `SESSION_TOKEN_SECRET 必须至少包含 32 个字节，且只能由运行时环境注入`。 |

生成一条随机密钥（推荐）：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

把输出整行贴进 `.env`：

```
SESSION_TOKEN_SECRET=这里粘贴上面命令的输出
```

### 3.2 建议一并填上

| 变量 | 作用 | 建议值 |
|---|---|---|
| `PORT` | 后端监听端口 | `5191`（前端开发服务器默认把 `/api` 代理到这个端口，不要改，除非你同时改代理） |
| `DATABASE_PATH` | SQLite 文件路径 | `server/data/readmate.sqlite` |
| `HOST` | 监听地址 | 可省略，默认 `127.0.0.1` |

### 3.3 登录演示可以不填

| 变量 | 不填会怎样 |
|---|---|
| `OPENAI_BASE_URL` / `OPENAI_API_KEY` / `MODEL_ID` | 登录、看页面不受影响；问答等 AI 功能会走确定性降级，不能当成外部模型结果 |
| `SUMMARY_LINK_SIGNING_KEY` | 登录不受影响；以后若要签发家长报告链接再填，同样建议用上面那条命令生成 |
| `INTERNAL_DEMO_PASSWORD` | **不要指望靠它创建本文的示例账号**。它只给仓库里另一条内部演示脚本用，见第 8 节 |

不要把填好密钥的 `.env` 提交进 Git。

## 4. 初始化数据库和示例账号

空库没有任何账号。请用仓库里的示例账号清单导入，**不要**把真实师生姓名写进清单。

示例账号文件：`scripts/sample-accounts.json`

| 登录名 | 显示名 | 角色 | 端 |
|---|---|---|---|
| `sample-principal` | 示例校长 | 校长 | 校长端 / 控制台 |
| `sample-teacher` | 示例教师 | 教师 | 教师端 / 控制台 |
| `sample-student-1` | 示例学生一 | 学生 | 学生端 |
| `sample-student-2` | 示例学生二 | 学生 | 学生端 |
| `sample-student-3` | 示例学生三 | 学生 | 学生端 |

- 三个学生和教师都属于 **示例班级**。教师端要能看到学生，靠的就是这条班级归属。
- **默认口令（五个账号相同）：`ChangeMe#Sample1`**
- 首次登录后立刻改口令，见第 7 节。

官方 `npm run seed:identity` **不能**直接吃这份清单：它只接受已经算好的 scrypt 哈希，明文口令会被拒绝。请用下面这条封装命令（它会哈希口令、跑数据库迁移、再调用既有导入器）：

```bash
node scripts/import-sample-accounts.mjs --database server/data/readmate.sqlite
```

成功时会打印 JSON，其中 `accounts` 列出五个登录名，`import.inserted` 大于 0。

同一份清单对同一库再跑一次是安全的：已经导入的组织 / 用户 / 班级会记为 `unchanged`，已经有口令哈希的账号不会被覆盖。如果改过清单里的姓名或班级再导入，会因稳定 ID 冲突而失败，需要换一个空库。

不要用 `npm run seed:identity` 直接导入这份清单。那条官方命令只认哈希、不认明文口令，结果会建成**没有登录口令**的账号，看起来成功、实际无法登录。

可用环境变量 `SAMPLE_ACCOUNTS_PASSWORD` 覆盖清单里的默认口令，不必改文件。

### 4.1 npm 传参的坑（请绕过）

`npm run <脚本> -- --database ...` 在 **npm 11** 下会把 `--database` 吞掉，当成 npm 自己的配置，脚本收不到参数。所以本文一律写成 `node 某个.js --database ...`，不要套 `npm run`。

## 5. 启动后端和前端

开两个终端，都在仓库根目录。

**终端 A：后端**

```bash
npm run server
```

成功时应看到类似：

```
[readmate] listening on http://127.0.0.1:5191
```

- 后端地址：`http://127.0.0.1:5191`
- 健康检查：`GET http://127.0.0.1:5191/api/v1/health`

**终端 B：前端（开发模式）**

```bash
npm run dev
```

成功时应看到 Vite 监听 `http://127.0.0.1:5190/`。若 5190 已被占用，Vite 可能会改去别的端口；开发代理仍然指向 5191，所以后端端口不要改。

- 前端地址：`http://127.0.0.1:5190`
- 浏览器里的 `/api` 会被 Vite 代理到 `http://127.0.0.1:5191`。这是写死在 `vite.config.js` 里的，所以开发模式下后端必须是 **5191**。

登录请走前端地址（5190），不要直接用后端 5191 打开页面——开发模式下 5191 不一定有最新前端。

## 6. 用示例账号登录三端

浏览器打开：

| 端 | 地址 | 用哪个账号 |
|---|---|---|
| 学生端 | http://127.0.0.1:5190/student/login | `sample-student-1`（或 2、3） |
| 教师端 | http://127.0.0.1:5190/console/login | `sample-teacher` |
| 校长端 | http://127.0.0.1:5190/console/login | `sample-principal` |

口令都是 `ChangeMe#Sample1`。登录框只有「账号 + 密码」两栏，**没有学校码**。

登录成功后的落地页：

- 学生 → `/student/home`
- 教师、校长 → `/console/home`

教师登录后工作空间是示例班级；校长在班级列表里应看到「示例班级」，学生人数 3、教师人数 1。

### 6.1 用命令行确认登录接口（可选）

登录接口是 `POST /api/v1/auth/login`，JSON **只有** `loginName` 和 `password` 两个字段，没有学校码。写请求必须带 `Idempotency-Key` 头，否则会 400。

Windows 上 PowerShell 的 `curl` 是 `Invoke-WebRequest` 的别名，请写 `curl.exe`。也不要把 JSON 塞进 PowerShell 单引号再交给 `--data-raw`：引号会被吃掉，后端可能直接 503。稳妥写法是先把请求体写成文件：

```powershell
Set-Content -Path login.json -Value '{"loginName":"sample-student-1","password":"ChangeMe#Sample1"}' -Encoding ASCII
curl.exe -s -D - -o - -X POST http://127.0.0.1:5191/api/v1/auth/login -H "Content-Type: application/json" -H "Idempotency-Key: demo-login-student-1" --data-binary "@login.json"
```

或用 Node（跨平台，不依赖 curl 引号）：

```bash
node --input-type=module -e "const r=await fetch('http://127.0.0.1:5191/api/v1/auth/login',{method:'POST',headers:{'Content-Type':'application/json','Idempotency-Key':'demo-login-student-1'},body:JSON.stringify({loginName:'sample-student-1',password:'ChangeMe#Sample1'})}); console.log(r.status); console.log(await r.text())"
```

成功：HTTP 200，响应体有 `data.user`，响应头有 `Set-Cookie: readmate_session=...`。口令错误：401，`账号或密码错误`。把 `loginName` 换成 `sample-teacher` / `sample-principal` 即可验另外两端。

## 7. 首次登录后必须做的事

示例口令写在仓库里，谁拿到源码都知道。登录成功后立刻改掉：

- 学生：右上角进入个人设置，或直接打开 http://127.0.0.1:5190/student/me/settings
- 教师 / 校长：控制台设置页 http://127.0.0.1:5190/console/settings

新密码至少 6 个字符。改完后当前登录仍然有效。

## 8. 不要和内部演示脚本混用

仓库里还有 `npm run bootstrap:internal`（入口是 `server/db/bootstrap-internal-demo.js`）。它**不会**读取 `scripts/sample-accounts.json`。

它真正要求的是：

- 环境变量 `INTERNAL_DEMO_PASSWORD`（至少 12 个字符）
- `--database` 数据库路径
- `--manifest`：**书目**清单，不是账号清单

仓库提供了一份空书目 `scripts/empty-public-domain-manifest.json`，只为了让这条命令在没有公版书素材时也能跑完身份初始化。即便如此，它创建的是脚本里写死的另一套账号，和本文示例校长 / 示例教师 / 示例学生不是同一批人。

**对接方请只用第 4 节的示例账号导入。** 不要把两条初始化命令打进同一个数据库。

若你在别的文档里看到 `npm run bootstrap:internal -- --database ...`，在 npm 11 下这条写法是坏的（`--database` 会被 npm 吃掉）。正确写法是直接调 Node：

```bash
node server/db/bootstrap-internal-demo.js --database server/data/readmate.sqlite --manifest scripts/empty-public-domain-manifest.json --public-root public
```

## 9. 常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 进程立刻退出，提示 `SESSION_TOKEN_SECRET 必须至少包含 32 个字节` | 会话密钥太短或没配 | 用第 3 节的 `node -e` 命令重新生成 |
| `必须提供 --database 与 --manifest` | 走了内部演示脚本，且 npm 把参数吞了 | 改用第 4 节的示例账号导入 |
| 登录 400，提示需要 `Idempotency-Key` | 用 curl 漏了这个头 | 补上头；浏览器页面会自动带 |
| 登录 401 | 口令或登录名不对 | 登录名是 `sample-student-1` 这种，不是显示名「示例学生一」 |
| 教师端看不到学生 | 学生没有进该教师的班级 | 用这份清单导入即可；不要只建教师账号 |
| 前端页面能开，但登录失败 / 接口 404 | 后端没起，或后端不在 5191 | 先确认终端 A 打出了 `listening on http://127.0.0.1:5191` |
| `EADDRINUSE :::5191` 或 5190 | 端口已被占用 | 换一台空机器，或先关掉占用进程。开发模式下不要只改后端端口——前端代理仍指向 5191 |
| 登录接口 503 | Windows 上 curl 的 JSON 被 PowerShell 吃掉 | 用 `--data-binary @login.json` 或上面的 `node --input-type=module` 写法 |

## 10. 本指南里哪些命令是在占用端口的机器上换写法验证的

空机器按第 5 节用 5190 / 5191 即可。写本文时本机这两端口已有别人的服务，因此：

- 后端是用 `PORT=5391` 加上临时 `DATABASE_PATH` 拉起的，命令仍是 `npm run server`
- 前端是用 `npx vite --port 5390 --strictPort --host 127.0.0.1` 确认 Vite 能起来；没有执行会占用 5190 的 `npm run dev`
- 没有执行 `Copy-Item .env.example .env`，以免覆盖已有 `.env`。对接方空机器仍应复制模板
- 登录、改口令、健康检查都是直接打 `http://127.0.0.1:5391/api/v1/...`，没有走 Vite 代理（代理写死 5191，会打到别人的后端）
