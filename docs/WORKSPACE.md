# 工作区边界

本仓库只保存可构建、可测试、可部署的应用工程内容。产品原始素材、历史交付包和内容解析工作区与应用源码分离。

## 应用仓库

| 路径 | 职责 |
|---|---|
| `src/` | 浏览器端代码；按主站、`student/`、`console/` 分区 |
| `server/` | API、领域逻辑、数据库迁移、模型与静态资源集成 |
| `tests/` | 与 `src/`、`server/` 对应的自动化测试 |
| `public/` | 随应用发布的小型稳定资源；`public/books/` 为运行时内容，不入Git |
| `docs/` | 当前架构、冻结契约和可复核验收记录 |
| `screenshots/` | 脱敏且仍有产品说明价值的效果图 |

全栈能力分布在 `src/` 和 `server/` 是前后端职责分离，不应为了目录表面集中而混放。同一功能的前端、服务端和测试分别位于其所属层；领域命名保持一致以便检索。

## 仓库之外

以下内容不得放入应用Git历史：

- 原始PDF、EPUB和扫描图片；
- OCR渲染页、模型输出、失败重试文件；
- 压缩包原件、历史交接包和需求材料副本；
- `node_modules/`、`dist/`、数据库文件和本地环境变量；
- 未脱敏账号、日志、截图或模型密钥。

本机约定：

```text
/Users/yak/Project/读伴书籍解析器/   原始书籍、解析代码、中间结果和发布包
/Users/yak/Project/读伴项目资料归档/ 历史交付包、需求材料与压缩包原件
```

## 书籍交付边界

独立解析工作区负责页面渲染、OCR、坐标校正、抽样验收和固定版本产物。应用部署阶段只执行受控的书籍登记，不在运行时提供教师上传或在线OCR。

应用侧必须保持以下边界：

1. 书籍二进制资源不写入业务数据库；数据库只保存元数据、正文、坐标与存储键。
2. 新书或修订书以不可变版本发布，不覆盖已经产生阅读记录的版本。
3. 部署脚本只登记已验收的书籍产物，不承担解析或模型调用。
4. 任何本地绝对路径在进入数据库前必须转换为存储系统内的相对键。
